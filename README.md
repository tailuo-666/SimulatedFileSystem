# 模拟磁盘文件系统（Simulated File System）

> 操作系统课程设计 · 基于 Java 17 + Swing 实现的可运行文件系统

---

## 一、项目简介

本项目用 Java 实现了一个**真正落在磁盘映像文件上**的模拟文件系统，而不是在内存集合里"假装"建文件。

所有操作最终都会变成对 `data/disk.img` 这一块 **8192 字节** 的模拟磁盘的读写：

- 磁盘被划分成 **128 个物理块**，每块 **64 字节**；
- 前两块（0、1）存放 **FAT 文件分配表**（128 项 × 1 字节）；
- 第 2 块是**根目录**，固定 8 个目录项；
- 第 3～127 块是数据块和子目录块，其中 **23、49 是坏块**；
- 文件采用**显式链接**的物理结构：目录项记录起始块，之后靠 FAT 一项一项串下去，最后一块是 EOF(255)。

界面是完整的 Swing 桌面程序，提供目录树、文件列表、磁盘空间可视化（16×8 网格）、FAT 表查看、磁盘块字节查看器四大视图，所有展示内容都实时从模拟磁盘读出。

关闭程序再启动，文件、目录、FAT 全部原样保留。

## 六、FAT 表的工作原理

FAT 是"显式链接"的核心：**每一项记录同一个文件的下一个块号**，相当于链表里的 next 指针。

| FAT 值 | 含义 |
|---|---|
| 0 | 空闲块 |
| 1 ~ 127 | 指向下一块 |
| 253 | 系统保留（块 0、1、2） |
| 254 | 坏块 |
| 255 | EOF，文件最后一块 |

举例：`/DOC/SUB/C.TX` 从第 9 块开始，内容 100 字节，占 2 块：

```text
目录项 startBlock = 9
FAT[9]  = 10      → 下一块是 10
FAT[10] = 255     → EOF，链结束
```

实际 `disk.img` 前 16 个字节（十六进制，即 FAT[0] ~ FAT[15]）：

```text
FD FD FD FF FF FF FF FF FF 0A FF FF 00 00 00 00
└─┬──┘ │  │  │  │  │  │  └┬─┘ │  │
253  253 253 │  │  │  │  │  10  │  └── 12 起全为 0（空闲）
             │  │  │  │  │      └── 11: EOF（/DAT/TST.TX）
             │  │  │  │  └── 9: 指向 10（C.TX 第一块）
             │  │  │  └── 8: EOF（B.TX）
             │  │  └── 7: EOF（A.TX）
             │  └── 5,6: EOF（DAT、TMP 两个目录块）
             └── 3,4: EOF（DOC、SUB 两个目录块）
```

**易错点**：Java 的 `byte` 是有符号的（-128~127），直接读取会把 253/254/255 读成负数。所以读盘时必须 `value & 0xFF` 转成 0~255 的无符号整数，写盘时再强制转换回去。这一点在整个项目里统一处理（FAT、目录项属性、起始块号、长度字段都一样）。

链遍历的安全检查（`FatTable.chainOf`）：

1. 块号必须在 0~127；
2. 同一块不能出现两次（防止 FAT 被改成环，导致死循环）；
3. 遇到 255 / 253 结束，遇到 0 说明链断了（容错结束）。

## 七、目录项数据结构

每个目录项固定 **8 字节**，文件和目录共用同一套字节布局：

| 偏移 | 文件目录项 | 目录目录项 |
|---|---|---|
| 0~2 | 主文件名（3 字节，不足补 0x00） | 目录名（3 字节） |
| 3~4 | 扩展名（2 字节） | 保留（全 0） |
| 5 | 属性（1 字节） | 属性（1 字节，固定 8） |
| 6 | 起始盘块号（1 字节） | 起始盘块号（1 字节） |
| 7 | 占用块数（1 字节） | 保留（全 0） |

- 空目录项的标志：**第一个字节是 `'$'`（0x24）**。
- 属性字节：`1` 只读，`4` 普通可读写，`8` 目录（bit0 只读、bit1 系统、bit2 普通、bit3 目录）。
- 名称只允许 ASCII 字母、数字、下划线：主名 ≤ 3 字符，扩展名 ≤ 2 字符，目录名 ≤ 3 字符；不允许 `$`、`.`、`/`。
- 名称比较**大小写不敏感**（内部统一存大写）。

真实的根目录块（第 2 块，64 字节，演示数据）：

```text
44 4F 43 00 00 08 03 00 | 44 41 54 00 00 08 05 00 | 54 4D 50 00 00 08 06 00 | 24 24 24 ...
└─── "DOC" ───┘ 属性8 块3   └─── "DAT" ───┘ 属性8 块5   └─── "TMP" ───┘ 属性8 块6   空项
```

再比如 `/DOC` 目录块的 48 字节：

```text
53 55 42 00 00 08 04 00 | 41 00 00 54 58 04 07 01 | 42 00 00 54 58 01 08 01 | 24 ...
 "SUB"      属性8 块4      "A" .. "TX" 属性4 块7 1块    "B" .. "TX" 属性1 块8 1块   空项
```

> 注意 `04 07 01` 三个字节：属性 4（可读写）、起始块 7、占用 1 块；而 B.TX 是 `01 08 01`，属性 1 表示**只读**。

## 八、文件物理结构（显式链接）

文件是**流式逻辑结构**，物理上采用**显式链接**：

```text
/DOC/SUB/C.TX  →  9 → 10 → EOF
```

- 目录项只记录**起始块号**和**占用块数**；
- 每个块内部按字节顺序存内容，**末尾追加一个 `'#'` 作为文件结束标志**；
- 占用的块数 = ⌈(内容字节数 + 1) / 64⌉，最少 1 块（空文件也有一个 `'#'`）；
- 目录项里的"长度"字段记录的是**块数**，不是字符数；真实字节数要靠读到 `'#'` 为止来算。

第 7 块（`/DOC/A.TX`，内容 `HelloWorld`）：

```text
48 65 6C 6C 6F 57 6F 72 6C 64 23 00 00 ...
 H  e  l  l  o  W  o  r  l  d  #  ← 结束符，后面是补 0
```

UTF-8 中文字符的每个字节都 ≥ 0x80，`'#'`(0x23) 不可能出现在多字节字符中间，所以用 `'#'` 截断不会把汉字劈成两半。

**块归属是怎么算出来的**：FAT 里没有、也不能存文件名。界面上的"这块属于哪个文件"是每次刷新时现算的：递归遍历目录树 → 读每个目录项 → 沿 FAT 链把链上每块登记到 `块号 → 绝对路径` 的映射里。如果发现某块已分配却找不到归属，或者两个文件共享了同一块，就标成**异常块**（紫红色），绝不默默忽略。

## 九、文件打开表 OFT

用长度 5 的数组模拟（`OpenFileTable`），系统最多同时打开 5 个文件。

每个表项（`OpenFileEntry`）记录：

| 字段 | 含义 |
|---|---|
| absolutePath | 绝对路径 |
| attribute | 属性（只读 / 可读写） |
| startBlock | 起始盘块号 |
| lengthBytes | **实际内容字节数**（不含 `'#'`） |
| blockCount | **占用块数**（目录项里的长度字段） |
| operationType | 0 读方式 / 1 写方式 |
| readPointer | 读指针（块号 + 块内偏移） |
| writePointer | 写指针（块号 + 块内偏移） |

规则：

- 同一个文件**不能重复登记**（否则两个表项各维护指针，一定会写乱）；
- 表满时打开第 6 个文件会被拒绝并提示；
- 打开时读指针指向文件开头，写指针指向文件末尾（追加起点）；
- 关闭时移除表项；以写方式打开的文件关闭时会重写一遍内容，确保末尾有 `'#'` 并把块数写回目录项。

`lengthBytes` 和 `blockCount` 是两回事，代码里严格区分，不要混用。

## 十、文件读写机制

### 10.1 指针为什么是"块号 + 块内偏移"

指针不记录"第几个字节"，而是记录 `(blockNumber, offset)`，这样才能真实体现显式链接：

```text
Pointer(9, 60)  →  下一字节在 9 号块的第 60 字节；
                    读到 64 就该跳到 FAT[9] 指向的 10 号块，偏移归 0
```

跨块读取时，逻辑位置 `linear` 换算成 `chain[linear/64]` 与 `linear%64`，读完自动推进指针。

### 10.2 追加写入（APPEND）

```text
原内容：Hello       追加：World       结果：HelloWorld
```

核心层先读出原内容，拼上新内容，再整体重写（复用原有块，不够才申请新块）。

### 10.3 覆盖写入（OVERWRITE）

```text
原内容：HelloWorld  覆盖：OperatingSystem   结果：OperatingSystem
```

直接用新内容替换。**尽量复用原有块**：新内容块数 ≤ 原有块数时一块也不申请，多的块被释放；块数变多才追加。

### 10.4 空间预检查与回滚

`FileManager.writeContent()` 的顺序是刻意的：

1. 算出需要几块，**先检查空闲块够不够**；不够就直接抛异常——此时一个字节都还没改，原文件完好；
2. 备份 FAT 快照；
3. 需要则追加新块到链尾；
4. 逐块写数据（每块先清零，避免残留旧内容）；
5. 块数变少就把多余的块释放；
6. 重建 FAT 链，最后把 FAT 落盘；
7. 中途任何异常 → 用快照回滚 FAT，保证不会留下半截链。

### 10.5 只读属性是真的生效

只读的判断放在核心层的 `writeFile()` 最前面：

```java
if (entry.isReadOnly()) {
    throw new FileSystemException("文件是只读属性，禁止写入：" + p);
}
```

所以**即使绕过界面直接调用 `FileSystemService.writeFile()`，也同样被拒绝**（有专门的单元测试验证这一点）。只读文件也不能以写方式打开。

## 十四、项目设计中的关键技术点

1. **按块 I/O，不整盘加载**
   `DiskManager` 只暴露 `readBlock` / `writeBlock`，每次严格 64 字节，并保留 `buffer1`/`buffer2` 两个 64 字节缓冲。上层（FAT、目录、文件）全部通过这两个方法访问磁盘，没有"把 8192 字节一次性读进数组"的偷懒做法。

2. **无符号处理**
   `byte` → `int` 统一用 `& 0xFF`，否则 253/254/255 会变成负数，FAT 链和属性判断全错。

3. **FAT 链遍历的三重保护**
   块号范围校验、重复块检测（防环）、断层容错，避免一个坏数据把程序拖进死循环。

4. **块归属靠推导而非存储**
   界面上的"某块属于哪个文件"每次刷新时由目录树 + FAT 链算出，绝不在 FAT 里塞额外信息（FAT 每项就 1 字节，也塞不下）。同时能识别"已分配无归属""多文件共享"两类异常。

5. **写入前预检查 + 失败回滚**
   先算块数、先查空闲，通过后才动数据；动数据前备份 FAT 快照，异常时恢复。空间不足时原文件不会被破坏（有测试用例）。

6. **指针模型忠于显式链接**
   读写指针 = 块号 + 块内偏移，跨块时按 FAT 链跳到下一块，不是用线性字节下标"假装"。

7. **分层彻底**
   核心层不 import 任何 `javax.swing`；界面层不 import `RandomAccessFile`。核心层的规则（只读、OFT 上限、目录容量、名称合法性）不依赖界面，命令行或单元测试直接调用同样生效。

8. **失败不留垃圾**
   建文件/建目录时先分配块，若后续写目录项失败，会把刚分配的块释放掉再抛异常。

9. **界面用标准布局管理器**
   `BorderLayout` + `JSplitPane` + `JScrollPane` + `GridBagLayout`，没有绝对坐标；在 1280×720、1366×768、1920×1080 下都能正常显示。

## 十五、当前实现的限制

1. **目录不能动态扩展**：每个目录固定 1 块 = 8 个目录项（课程要求"不要求实现动态扩展目录"）。根目录同样只有 8 个。
2. **文件名只支持 ASCII**：主名 ≤ 3、扩展名 ≤ 2 个字符；中文文件名不支持（目录项只有 3 字节名称字段，一个汉字 UTF-8 要占 3 字节，剩不下扩展名）。**文件内容是完整支持中文的**。
3. **正文不能含 `'#'`**：`'#'` 是结束符，输入时会被拒绝（界面和核心层双重校验）。
4. **单文件最大 123 块**（7872 字节），受磁盘总容量限制；目录项里的块数字段是 1 字节，理论最大 255，当前磁盘规模下不会触及。
5. **文件不覆盖写指针之外的随机定位**：只实现了顺序读写 + 追加 + 覆盖三种语义，没有实现 `seek`。
6. **无权限/多用户概念**：只有"只读/可读写"这一个属性位在起作用，`ATTR_SYSTEM` 位保留但界面未提供开关。
7. **不做磁盘碎片整理**：块分配是从 3 号块向后找第一个空闲块，删除后会产生碎片，但不影响正确性。
8. **无并发控制**：单进程单线程使用，没有加文件锁。同一目录被两个程序同时打开不在考虑范围内。
9. **界面文字为中文且未做国际化**。
10. **FAT 常驻内存**：FAT 表（128 字节）在内存里保留一份缓存，每次修改后立即写回块 0、1；文件内容块不缓存，始终按需读盘。

## 十七、规格说明与设计依据

课程说明里有两处小的自相矛盾，这里说明取舍：

1. **目录名长度**：要求"目录名最多 3 个字符"，但示例目录树里出现了 `DATA`、`TEMP`（4 个字符）。
   → **以"最多 3 个字符"这条硬性规定为准**，示例中的 `DATA` / `TEMP` 在本项目中写成 `DAT` / `TMP`。这是为了不让目录名超过 3 字节名称字段、破坏目录项结构。

2. **目录项结构**：文件目录项是"名称3 + 类型2 + 属性1 + 起始1 + 长度1"，目录目录项是"名称3 + 保留2 + 属性1 + 起始1 + 保留1"。
   → 两者的**字节位置完全对应**（属性都在偏移 5、起始块都在偏移 6），所以代码里用同一套解析/写入逻辑：先读偏移 5 的属性判断类型，是文件才去偏移 3~4 取扩展名、偏移 7 取块数，是目录就把这两处当保留字段。这样既符合课程给的结构，又不用写两套代码。

3. **FAT 值 253**：课程在原 FAT 定义上增加了 253 表示"系统保留"，本项目严格采用：块 0、1、2 的 FAT 值为 253，编译期常量集中在 `Constants.FAT_SYSTEM`。

4. **"长度"字段的含义**：目录项里的长度字段记录**占用块数**（按课程要求），不是字符数。真实字节数通过读到 `'#'` 为止计算，界面上两个数字分开显示，避免混淆。

## 十八、附：几个便于讲解的细节

**为什么空文件也占 1 块？**
因为要存一个 `'#'` 结束符。块数的计算是 `⌈(字节数 + 1) / 64⌉`，最小 1 块。

**为什么删除文件后块会"变回浅灰"？**
`deleteFile` 会 `fat.freeChain(startBlock)` 把整条链上每个块的 FAT 值改成 0，界面再根据 FAT 重新上色。不是只改界面数字。

**为什么属性改成只读之后，界面上"写入"按钮变灰还不够？**
因为界面可能被绕过（比如直接调 API、或别人改代码）。真正的判断在 `FileSystemService.writeFile()` 开头，抛 `FileSystemException`，这一条有单元测试专门验证。

**FAT 表为什么正好占两块？**
128 项 × 1 字节 = 128 字节 = 2 × 64 字节，所以块 0 存前 64 项、块 1 存后 64 项。`FatTable.save()` 就是按这个分界写的。
